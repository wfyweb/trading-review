# 数据模型与计算口径说明

> 版本 v1.0 · 2026-11-04
> 本文是对《短线合约交易复盘系统设计》的补齐与定稿，所有口径以此文为准。
> 原则：**宁可显示"不可计算"，也不输出假精确的数字。**

---

## 一、7 项决策总览

| # | 原缺口 | 决策 | 关键理由 |
|---|---|---|---|
| 1 | Prisma schema 与功能文档不一致 | 补齐 5 张表（Strategy / Tag / TradeTag / TradeFill / Ledger / EquitySnapshot），Trade 增补 12 个字段 | 没有标签表，标签体系就是 PPT 功能；没有 TradeFill，配对错了无法回溯 |
| 2 | 净收益公式两个版本 | 统一为 `netPnl = grossPnl - tradingFee + fundingFee`，并增加**交叉校验告警** | 唯一能落地的口径；靠校验兜住数据源差异 |
| 3 | 权益曲线无初始资金、无资金划转处理 | 初始资金 10 USDT 可配置；划转单列，**不计入收益**；回撤基于剔除划转后的交易权益 | 充值当盈利、提币当回撤，是最常见的假曲线来源 |
| 4 | 双向持仓 | 第一版只支持单向持仓，但**同步时探测账户模式**，不匹配则拒绝自动配对并提示 | 探测比假设安全；字段预留，未来支持 hedge 不改表 |
| 5 | K 线历史深度限制 | 本期不做 K 线，字段保留 nullable，UI 显示"未计算" | 用户决策：先不做 |
| 6 | R 倍数依赖人工止损 | 主口径 = 计划止损距离；无止损则 R 为 null **并从 R 统计中剔除**（不按 0 计入） | 用 0 顶替会系统性拉低期望值 |
| 7 | 移动端与本地 Web 冲突 | 只做本地 Web 桌面版，最小宽度 1280，不做响应式 | 用户决策 |
| 附 | 手续费币种复杂 | 只统计 USDT 计价手续费；非 USDT 记为 0 并打 `feeUnconverted` 标记，UI 明示 | 先跑通主流程，折算方案列入后期讨论 |

## 二、决策详述

### 决策 1：数据模型补齐

原 schema 缺失导致三个功能无法落地，补齐如下：

**① 金额精度：全部用 String 存十进制文本**

Prisma 在 SQLite 下的 `Decimal` 最终落到 NUMERIC 亲和性列，实际可能被存成 REAL，属于隐性精度丢失。
决策：

- **所有价格 / 数量 / 金额 / 比率字段类型为 `String`**，存规范化十进制文本（如 `"62123.45"`、`"-0.0132"`）。
- 所有运算在服务层用 `decimal.js`，**全程禁止 `number` 参与金额计算**。
- 比率类（rMultiple、胜率、回撤）保留 4 位小数后转字符串返回。
- 排序 / 聚合不在 SQL 里做，在服务层用 decimal.js 比较（本地单用户，千级数据量无性能问题）。

**② 新增 TradeFill 关联表**

原 schema 中 `Trade` 与 `Fill` 无关联，意味着一笔交易是由哪几笔成交组成的无法回溯，配对算法一旦调整（或误配）就无法重算。
用关联表而非外键直连，是为了支持一笔记账级 fill 被拆分到多个交易的情形（反手场景）：

```
TradeFill { tradeId, fillId, role: ENTRY | EXIT | ADJUST, quantity }
```

**③ 新增四张表**

| 表 | 为什么必须有 |
|---|---|
| `Strategy` | 原 schema 只有 `Trade.strategyId` 字符串，没有实体表，无法维护策略名称/规则/启停 |
| `Tag` + `TradeTag` | 亏损原因标签、违规标签是复盘的核心产出，原 schema 完全没有承载 |
| `Ledger` | 资金流水是净收益中资金费率的唯一来源，`SyncJob.ledgerCount` 存在却没有落表 |
| `EquitySnapshot` | 权益曲线每日快照，避免每次全量重算；同时用于与交易所余额对账 |

**④ Trade 增补字段**

`initialStopPrice`（首次开仓时的止损价）、`finalStopPrice`、`takeProfitPrice`、`riskAmount`（计划风险金额）、`margin`（保证金）、`plannedLeverage`、`holdingSeconds`、`marketRegime`（行情环境标签）、`setupType`（形态类型）、`netPnlEstimated`、`missingComponents`、`feeUnconverted`、`rMultipleSource`。

### 决策 2：净收益唯一口径

```
grossPnl    = Σ 平仓成交的已实现盈亏（交易所给的 execPnl，不含手续费）
tradingFee  = Σ 全部成交的 USDT 手续费（开仓 + 平仓）
fundingFee  = Σ 资金费率流水（带符号：收入为正、支出为负）
otherCost   = Σ 可确认的其他成本（滑点等，第一版恒为 0）

netPnl      = grossPnl - tradingFee + fundingFee - otherCost
```

**符号约定**（必须写进代码注释，这是最容易错的地方）：
Bitget 流水返回的资金费通常是负数表示支出。入库前统一转换为"对交易者现金流方向"：支出为负、收入为正。因此公式中资金费率恒为 `+`。

**交叉校验（新增，重要）**

交易所返回的 `execPnl` 与 `(exitPrice - entryPrice) × qty × 方向` 理论应一致。若偏差超过 0.01%，标记 `pnlMismatch = true` 并在 UI 上显示黄色警示。这是发现"手续费重复扣减""价格取错"的唯一低成本手段。

**估算标记**

任一组成项缺失时，返回：

```json
{ "value": "12.34", "isEstimated": true, "missingComponents": ["funding_fee"] }
```

前端必须显示「估算值」角标。**不允许把估算值当精确值参与排名与诊断**，诊断模块只使用 `netPnlEstimated = false` 的样本。

### 决策 3：权益曲线与 10 USDT 初始资金

**初始资金**

`Account.baselineCapital`，默认 `"10"`（10 USDT），可在设置页修改。

**两个权益概念，必须分开**

```
交易权益 tradingEquity(t) = baselineCapital + Σ netPnl(≤t)
账户权益 accountEquity(t) = tradingEquity(t) + Σ 净划转(≤t)
```

- **回撤、收益率、曲线形态一律基于 `tradingEquity`** —— 划转不影响交易能力评价。
- `accountEquity` 仅用于和交易所实际余额对账，不进入任何绩效指标。
- 资金划转（`TRANSFER_IN` / `TRANSFER_OUT`）在 `Ledger` 中作为独立类型，永远不计入盈亏。

**回撤计算**

```
peak(t) = max(tradingEquity(0..t))
drawdown(t) = (tradingEquity(t) - peak(t)) / peak(t)     # 负数
maxDrawdown = min(drawdown)
```

`peak` 从 `baselineCapital` 开始，因此**第一笔交易亏损就立即产生回撤**，不会被掩盖。

**10 USDT 起手的现实提醒（写进产品文案）**

10U 账户有两个结构性劣势，复盘系统必须把它显性化，否则用户会误判自己是"策略不行"：

1. **手续费占比极高**。Bitget 永续 Taker 约 0.06%，10U 本金、10 倍杠杆、单笔名义 100U 时，开平一轮手续费约 0.12U，即本金的 1.2%。若单笔盈利目标只有 3%，手续费就吃掉 40%。
2. **最小下单量约束**。部分币种最小名义额 5U，10U 本金无法分散，天然只能单币重仓。

因此概览页固定展示「手续费 / 净收益」与「手续费 / 初始资金」两个比率，并在超过阈值时给出提示。

### 决策 4：双向持仓

**第一版范围**：仅支持单向持仓（one-way mode）的 USDT 永续合约。

**但要探测，不要假设**：

```
同步开始前调用账户接口读取 posMode
  ├── one_way_mode  → 正常自动配对
  └── hedge_mode    → 中止自动配对，写入同步日志：
                      "当前账户为双向持仓模式，第一版不支持自动配对。
                       请切换到单向持仓，或改用 CSV / 手动录入。"
```

`Order` / `Fill` / `Trade` 三个表都保留 `positionSide` 字段（`BOTH` / `LONG` / `SHORT`），未来支持 hedge mode 时不需要改表结构。

**配对算法第一版（简化版，可解释）**

按 `symbol` 分组，按时间升序扫描成交：

```
1. 同方向成交 → 累加到当前持仓，更新平均开仓价，记 ENTRY
2. 反方向成交且数量 < 当前持仓 → 部分平仓，按比例分摊成本，记 EXIT
3. 反方向成交且数量 == 当前持仓 → 平仓完成，生成一个 Trade
4. 反方向成交且数量 > 当前持仓 → 先平完（生成 Trade），剩余数量开反向新仓
5. 到期末仍有持仓 → 生成 status = OPEN 的 Trade
```

无法满足上述任一条件的数据（如跨期缺口、数据丢失）→ `matchingStatus = NEEDS_REVIEW`，进入人工确认队列，**不参与统计**。

### 决策 5：K 线（本期不做）

- Prisma 保留 `mfe` / `mae` 字段，类型 `String?`，本期恒为 `null`。
- UI 显示"未计算"，不显示 `0`。
- 单笔复盘页的图表区降级为**价格轨迹图**：只用该笔交易的成交点（开仓/加仓/减仓/平仓）连线，不依赖任何外部行情 API。
- 后期接入 K 线时替换该组件即可，不影响数据层。

### 决策 6：R 倍数口径

**主口径（唯一入统计的口径）**

```
plannedRisk = |entryPrice - initialStopPrice| × quantity
rMultiple   = netPnl / plannedRisk
```

`initialStopPrice` 是**首次开仓时**的止损价，不是事后调整的止损。

**缺失处理**

| 情况 | rMultiple | 是否进入 R 统计 |
|---|---|---|
| 有 `initialStopPrice` 且 `plannedRisk > 0` | 正常计算 | 是 |
| 无 `initialStopPrice` | `null`，`rMultipleSource = "NONE"` | **否** |
| `plannedRisk == 0`（止损价等于开仓价） | `null`，标记异常 | 否 |

**绝不用 0 或最大亏损顶替**。统计期望值时同时给出两个口径：

- `expectancyR`：仅 R 可用样本，同时显示 `sampleSize`（如 `N=14 / 总 20 笔`）
- `expectancyUsdt`：全样本

**如何降低填写负担（产品手段，而非妥协）**

1. 若交易来自止损单，从订单数据自动推导 `initialStopPrice`。
2. 单笔复盘页在 `initialStopPrice` 为空时，顶部显示一条可点击的行动项：「补齐止损价即可计算 R 倍数」，点击即聚焦该输入框。
3. 概览页对「R 覆盖率」做单独展示（如 `14/20 笔有 R`），让缺失可见，而不是悄悄失真。

### 决策 6.1：杠杆与保证金（实测约束下的折中方案）

**实测结论（2026-11-09，真实密钥）**：Bitget 统一账户拿不到历史单的杠杆与保证金。

| 接口 | 结果 |
|---|---|
| `v2 /mix/position/history-position` | 400 / 40085「统一账户模式，暂不支持调用经典账户接口」 |
| `v3 /position/history-position` | 200，20 个字段，**无 leverage / marginSize** |
| `v3 /trade/history-orders` | 200，33 个字段，**无 leverage** |
| `v3 /position/position-detail` | 404 不存在 |
| `v3 /position/current-position` | 200，**有 leverage / marginSize**，但只返回当前仍开着的仓位 |

**因此采用双轨口径**：

| 字段 | 来源 | 算法 |
|---|---|---|
| `actualLeverage` / `margin` | 交易所（`leverageSource = EXCHANGE`） | 直接取 current-position 的 leverage / marginSize |
| 同上 | 估算（`leverageSource = ESTIMATED`） | `equityAtEntry = 初始资金 + 开仓前已平仓净收益 + 开仓前净划转`；`leverage = 名义仓位 ÷ equityAtEntry`；全仓下 `margin = equityAtEntry` |

**边界（不许越线）**：

1. 交易所真值优先，估算永不覆盖；
2. `equityAtEntry ≤ 0` 时不算（分母非正无意义），杠杆留空并在 UI 说明；
3. 逐仓不推算保证金（占用与权益无关）；
4. 估算值在 UI 一律带 `≈`，导出 Excel 有「杠杆来源」列区分；
5. 这是**权益杠杆**，衡量仓位相对账户的重量，与交易所显示的杠杆倍数不是同一个数；不含浮盈浮亏与未入账资金费率。


**止损与止盈数据的可达性（实测）**

| 场景 | 交易所是否可查 | 处理 |
|---|---|---|
| 下单时就附带止盈止损 | ✅ 订单历史带 `stopLoss` / `takeProfit` 字段 | 提取为 `initialStopPrice`，重算 `riskAmount` 与 `rMultiple`（来源 `PLANNED_STOP`） |
| 事后在持仓上单独设置 | ⚠️ 触发时的平仓单带 `delegateType = pos_loss_market / pos_profit_market`，但**触发价不落库**；UTA 无历史计划委托接口（v2 报 40085，v3 404） | 只判定 `exitType`（离场方式），**不把触发成交价当止损价**，否则 R 恒为 ±1 |
| 强制平仓 | ✅ 成交 `tradeSide = burst_close_*` | `isLiquidation` + `exitType = LIQUIDATION` |

`exitType` 取值：`STOP_LOSS | TAKE_PROFIT | LIQUIDATION | REVERSE | MANUAL`（来自平仓单 `delegateType`，强平优先级最高）。

### 决策 7：只做本地 Web 桌面版

- 不做响应式，最小内容宽度 1280px，低于该宽度出现横向滚动。
- 原文档验收标准中「移动端至少可查看并编辑单笔复盘」一条**作废**，改为「桌面浏览器 1280px 以上可用」。
- 后续如需移动端，走独立只读 H5，不复用桌面布局。

### 附：手续费只统计 USDT（本期方案，后期需讨论）

**处理规则**

| 情况 | 处理 |
|---|---|
| `feeCoin == "USDT"` | 正常计入 `tradingFee` |
| `feeCoin != "USDT"`（如 BGB 抵扣） | `fee` 记 `0`，`feeUnconverted = true` |
| 手续费为 0 或缺失 | `feeUnconverted = true`，`missingComponents` 追加 `trading_fee` |

**UI 义务**

- 交易列表对该类交易显示 `费?` 角标。
- 单笔详情页显示：「该笔含非 USDT 计价手续费，未计入净收益，当前净收益偏高。」
- 概览页汇总显示「N 笔含未折算手续费」，点击可筛选。

**后期讨论议题（已记录，本期不实现）**

1. BGB 抵扣折扣后的实际费率折算
2. 非 USDT 手续费按成交时刻市价折算，还是按日终价折算
3. 手续费返还 / 返佣（rebate）的归属与是否冲减成本
4. 多币种账户下统一计价货币的选择

## 三、完整数据模型

见 `apps/api/prisma/schema.prisma`，以下为字段级说明。

### Account 账户

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String | cuid |
| name | String | 账户显示名 |
| exchange | String | 默认 BITGET |
| apiKey | String? | 公开 key，可明文 |
| secretRef | String? | **不存明文**，存系统钥匙串引用键 |
| passphraseRef | String? | 同上 |
| posMode | String? | one_way_mode / hedge_mode，同步时探测写入 |
| baselineCapital | String | 初始资金，默认 "10" |
| quoteCurrency | String | 默认 USDT |

### Order 订单（原始层）

交易所订单记录，原样留存 `rawPayload`。唯一键 `[accountId, exchangeOrderId]`。

### Fill 成交（原始层）

交易所成交记录，是配对算法的唯一输入。含 `feeCoin`、`fee`、`execPnl`、`positionSide`。唯一键 `[accountId, exchangeFillId]`。

### Trade 复合交易（派生层）

一轮完整持仓周期。**这是复盘的操作对象。**

分组字段：
- 基础：`symbol`、`direction`（LONG/SHORT）、`status`（OPEN/CLOSED）、`entryTime`、`exitTime`、`holdingSeconds`
- 价格数量：`entryPrice`（加权平均开仓价）、`exitPrice`（加权平均平仓价）、`quantity`
- 风险：`initialStopPrice`、`finalStopPrice`、`takeProfitPrice`、`riskAmount`、`margin`、`plannedLeverage`、`actualLeverage`（名义/保证金）
- 盈亏：`grossPnl`、`tradingFee`、`fundingFee`、`netPnl`、`netPnlEstimated`、`missingComponents`、`pnlMismatch`
- 绩效：`rMultiple`、`rMultipleSource`、`mfe`、`mae`（本期 null）
- 归类：`strategyId`、`marketRegime`、`setupType`
- 状态：`executionScore`、`reviewStatus`、`matchingStatus`、`feeUnconverted`

### TradeReview 复盘（人工层）

`entryReason`、`exitReason`、`marketContext`、`plannedSetup`、`actualProcess`、`planDeviation`、`emotion`、`followedPlan`、`reviewConclusion`、`improvementAction`、`screenshotPaths`（逗号分隔本地路径）、`reviewedAt`。

### Strategy 策略

`name`、`description`、`rules`（入场规则文本）、`isActive`。

### Tag 标签 + TradeTag

`category`：`MISTAKE`（违规/失误）/ `POSITIVE`（做对了）/ `MARKET`（行情环境）/ `SETUP`（形态）。
`polarity`：`POSITIVE` / `NEGATIVE` / `NEUTRAL`，用于诊断时区分"该扣分的"和"该加分的"。

### Ledger 资金流水

`type`：`TRADE_FEE` / `FUNDING` / `TRANSFER_IN` / `TRANSFER_OUT` / `REALIZED_PNL` / `OTHER`。
`amount` 带符号。`tradeId` 可空（用于把资金费率归属到具体交易）。

### EquitySnapshot 权益快照

`date`（YYYY-MM-DD）、`tradingEquity`、`accountEquity`、`peakEquity`、`drawdownPct`。

### SyncJob 同步任务

沿用原设计，增加 `posModeDetected`、`abortReason`。

## 四、诊断规则（第一版，透明可审计）

每条规则输出必须包含：`样本量 N`、`统计区间`、`触发阈值`、`关联交易 ID`、`计算时间`。

| 规则 | 触发条件 | 输出 |
|---|---|---|
| R1 策略失效 | 某策略 N ≥ 20 且 `expectancyR < 0` | 该策略需要重新评估 |
| R2 过度交易 | 单日交易笔数 > 近 30 日均值 × 2 | 检查是否情绪化加仓 |
| R3 连亏放大 | 连亏 ≥ 3 笔后，下一笔名义仓位 > 前 3 笔均值 × 1.5 | 报复性交易的典型特征 |
| R4 止损缺失 | 有回撤但无 `initialStopPrice` 的样本占比 > 30% | 风险不可量化 |
| R5 手续费侵蚀 | `tradingFee / |netPnl|` > 40% | 交易频率或杠杆结构需优化 |
| R6 计划偏离 | `followedPlan = false` 的样本占比 > 20% | 执行力问题而非策略问题 |
| R7 短线亏损 | 某持仓时长区间样本 ≥ 20 且每笔净期望 < 0 | 该时长区间的交易越做越亏 |
| R8 利润集中 | 最好 5% 交易贡献 > 80% 的利润（样本 ≥ 20） | 结果是行情给的，不是策略稳定产出 |
| R9 方向失衡 | 单方向占比 > 65% 且该方向净收益 < 0 | 方向偏好在拖累整体 |
| R10 手续费吞毛利 | 手续费 / |毛收益| > 50% | 成本吃掉了过半毛利 |

**规则样本不足时不输出结论，只显示"样本不足（N=6 / 需 20）"。**

## 五、计算口径速查表

| 指标 | 公式 | 备注 |
|---|---|---|
| 净收益 | `grossPnl - tradingFee + fundingFee` | 缺项标估算 |
| 胜率 | `netPnl > 0 的笔数 / 已平仓笔数` | 基于净收益，不是毛收益 |

| 最大回撤 | `min((equity - peak) / peak)` | 基于 tradingEquity |
| 收益率 | `ΣnetPnl / baselineCapital` | 10U 起手会很大，如实显示 |
| 手续费占比 | `ΣtradingFee / |ΣnetPnl|` | 10U 账户重点指标 |
