## 1. 背景与问题定义

### 1.1 用户处境

一个用 10 USDT 本金在 Bitget 做 USDT 永续短线合约的交易者。持仓周期几分钟到一小时，杠杆 5–20 倍，每天 1–5 笔，月均 50–100 笔。

他的原始数据是完整的——交易所里有订单、成交、手续费、资金费率。但他**没有任何工具把这些数据变成可行动的判断**。目前的做法是：翻交易所历史成交、截图、在备忘录里写两句"这笔追高了"。

### 1.2 真正的痛点

不是"看不到盈亏"，盈亏交易所已经算好了。痛点在四个说不清：

| # | 说不清的问题 | 现状 | 后果 |
|---|---|---|---|
| 1 | 哪些策略真的在赚钱 | 只记得最近两三笔的手感 | 好策略被一次大亏否决，坏策略被一次侥幸留下 |
| 2 | 亏损来自策略还是执行 | 两者混在一起 | 该改规则的时候去练心态，该练心态的时候去改规则 |
| 3 | 风险是否一直可控 | 只在大亏后才有感觉 | 杠杆和仓位随情绪漂移，直到爆一次 |
| 4 | 下一笔具体要改什么 | 复盘结论是"要更谨慎" | 不可执行，下次照旧 |

### 1.3 现有替代方案为什么不够

- **交易所历史记录**：只有成交，没有"这笔交易"的概念（加仓、部分平仓被拆成多条），没有执行评价，不能按策略聚合。
- **Excel 手工记账**：10U 本金下单笔盈亏只有几毛钱，手工记录的成本高于收益；且无法处理手续费、资金费率的归集。
- **第三方复盘工具**：需要授权 API、数据上云，且按"收益率"设计，对 10U 账户的费率损耗不敏感。

### 1.4 产品要回答的四个问题

1. 哪些策略和行情环境在赚钱？
2. 亏损哪些来自策略本身，哪些来自执行错误？
3. 风险是否一直在可控范围内？
4. 下一次交易具体改什么？

**这四个问题就是本文所有功能需求的取舍标准。** 任何功能如果不能帮助回答其中之一，不进 MVP。

## 2. 产品定位与设计原则

### 2.1 一句话定位

> 一个本地运行的交易复盘工作台：把交易所的成交数据，变成"结果 + 执行"两个维度的可审计结论。

### 2.2 三条不可妥协的设计原则

**P1｜结果与执行分离**
盈利不等于好交易，亏损不等于坏交易。系统必须能表达"这笔赚钱了，但执行是错的"（如连亏后重仓赌回来），也能表达"这笔亏了，但执行是对的"（如严格止损）。因此执行评分和复盘结论必须独立于盈亏存在。

**P2｜宁可空着，不给假精确**
数据缺失时显示"不可计算 / 未计算 / 估算值"，绝不用 0 或估值顶替。一条错误的精确数字比一个诚实空白危害大得多——它会污染后续所有统计。

**P3｜主观信息交还用户**
入场理由、当时情绪、是否按计划执行，这些只有交易者本人知道。系统不做 AI 揣测（见 2.4），只提供结构化的填写位置和后续的规则式归因。

### 2.3 三条体验原则

- **先看结论，再看过程**：概览页第一屏回答"我现在怎么样"，细节全部下沉。
- **每个数字都能追溯到交易**：任何统计结论都能点开看到构成它的那几笔。
- **不用学习成本换功能**：单页应用，6 个页面，全部中文，无向导、无配置流程。

### 2.4 明确不做（含理由）

| 不做 | 理由 |
|---|---|
| AI 自动判断情绪 / FOMO | 只能做概率推断，会被当成事实；误导代价高于收益 |
| 自动生成入场逻辑 | 主观意图不在任何 API 里，编造等于污染数据 |
| 自动优化策略参数 | 样本量根本不够，必然过拟合 |
| 实时爆仓预警 | 需要标记价格、维持保证金模型的实时精度，做不准不如不做 |
| 自动下单 / 平仓 | 超出复盘工具边界，风险不可接受 |
| 多用户 / 权限 | 单用户本地工具，引入即增加复杂度 |
| 云端同步 | 交易数据敏感，本地优先是产品立场而非技术妥协 |

## 3. 目标用户与使用场景

### 3.1 用户画像

| 维度 | 描述 |
|---|---|
| 身份 | 个人交易者，兼职或全职短线 |
| 本金 | 10–100 USDT 起（首版按 10 USDT 校准） |
| 品种 | Bitget USDT 永续，单向持仓 |
| 频率 | 每天 1–5 笔，持仓分钟级 |
| 技术能力 | 能装 Node、跑命令行、看得懂 JSON（本产品不做安装包） |
| 设备 | Mac / Windows 桌面浏览器，不移动 |
| 关键约束 | 不愿把 API 密钥交给第三方；不接受数据上云 |

### 3.2 三个核心使用时刻

**场景 A｜盘后 15 分钟复盘（高频，每天）**
收盘后打开概览，看今天两笔的净收益和执行分，逐笔填写复盘表单，打标签。目标：把当天的记忆固化成结构化数据。

**场景 B｜周度策略体检（中频，每周）**
看策略分析页，检查每个策略的样本量、期望值、盈亏比。目标：决定下周主做哪个策略、停掉哪个。

**场景 C｜连亏后的诊断（低频，触发式）**
连续亏损 3 笔以上时打开诊断页，看命中了哪些规则。目标：区分"策略失效"还是"报复性交易"，决定是停手一天还是改规则。

### 3.3 反场景（不适用）

- 想要实时盯盘、看持仓浮盈 → 用交易所 App。
- 想要自动跟单、信号推送 → 不是本产品。
- 想要历史 K 线级别的行情复盘 → MVP-1 不做，见 §5。

## 4. 术语表

| 术语 | 定义 |
|---|---|
| 交易（Trade） | 一轮完整持仓周期，从首次开仓到完全平仓。加仓、部分平仓都属于同一笔交易 |
| 成交（Fill） | 交易所层面的一次撮合，一笔交易由多笔成交组成 |
| 毛收益 | 交易所给出的已实现盈亏，不含手续费 |
| 净收益 | 毛收益 − 手续费 + 资金费率，本文所有"盈亏"默认指净收益 |
| R 倍数 | 净收益 ÷ 计划风险金额（开仓价与首止损的距离 × 数量） |
| 执行评分 | 0–100，衡量"是否按计划执行"，与盈亏无关 |
| 计划风险 | 开仓时就已决定的最大可接受亏损额 |
| 待复盘 | 已平仓但尚未填写复盘记录的交易 |
| 估算值 | 因手续费或资金费率缺失而无法精确计算的净收益 |

## 5. 范围与版本规划

### 5.1 版本切分

| 版本 | 目标 | 核心能力 | 状态 |
|---|---|---|---|
| **MVP-1** | 验证数据模型与复盘流程 | 手动/CSV 录入、交易列表、6 项统计、权益曲线、单笔复盘、标签、规则诊断 | **已实现** |
| **MVP-2** | 不再手工录入 | Bitget 只读 API 接入、订单/成交/流水同步、成交配对、资金费率归集、同步日志与重算 | **已实现（Mock 模式验证通过；真实密钥待你自测）** |
| MVP-3 | 深度复盘 | K 线重建、MFE/MAE、执行评分自动化（滑点统计：用户决策不做） | 进行中（K 线 + MFE/MAE 已完成） |
| 暂缓 | — | 实时 WebSocket、爆仓预测、非 USDT 手续费折算、移动端、多账户 | 见 §2.4 |

### 5.2 MVP-1 的边界

**包含**：单账户、USDT 永续、单向持仓、已完成交易（持仓中的也能记录但不参与统计）、全量历史（不做分页加载优化）。

**不包含**：任何交易所 API 调用（完全离线可用）、行情数据、截图上传、CSV 导出、多账户切换。

## 8. 页面需求

### 8.1 P-01 概览

**目标**：30 秒内回答"我现在整体怎么样、哪里有问题"。

**布局（自上而下）**

1. **数据质量提醒条**（条件显示）：存在估算值 / 未折算手续费 / 校验不一致时出现，说明"这些笔的净收益可能偏离真实值"。
2. **核心指标区**（6 张卡，单行）：
   | 指标 | 主值 | 副信息 | 着色 |
   |---|---|---|---|
   | 净收益 | 累计净收益（USDT） | 收益率 + 本金 | 正负着色 |
   | 胜率 | 百分比 | X 胜 / Y 负 · 共 N 笔 | 中性 |
   | 盈亏比 | Profit Factor | 平均盈利 / 平均亏损 | 中性 |
   | 期望值 | 每笔期望（USDT） | R 期望 + R 样本量 | 正负着色 |
   | 最大回撤 | 百分比 | 当前权益 | 恒为负色 |
   | 手续费占比 | 手续费 ÷ \|净收益\| | 累计手续费金额 | >40% 时警示色 |
3. **权益曲线 + 回撤**（左侧 2/3）：面积折线，标注初始资金基准线，鼠标悬停显示该点权益、该笔盈亏、回撤。下方 90px 高度回撤柱状图。
4. **数据与风险卡**（右侧 1/3）：交易笔数、平均持仓、最大单笔盈利/亏损、缺开仓止损笔数、R 覆盖率、待确认配对笔数。
5. **待复盘列表**：最近 5 笔未复盘交易，点击直达详情。
6. **策略表现表**：策略 / 样本 / 胜率 / 净收益 / 期望值 / 盈亏比 / R 期望 / 结论徽章。样本 < 20 显示"样本不足"徽章，不下结论。

**关键规则**
- 权益曲线基于「交易权益」= 初始资金 + 累计净收益，**不含资金划转**（见 01 §决策 3）。
- 曲线从初始资金开始，因此第一笔亏损立即体现为回撤，不被前序盈利掩盖。
- 手续费占比 > 40% 时主值转警示色，这是 10U 账户最容易被忽略的结构性成本。

**验收标准**
- [ ] 六张卡的数值与 `/api/analytics/overview` 一致，无前端二次计算
- [ ] 鼠标悬停曲线任意点，能显示该点的权益、该笔净收益、回撤百分比
- [ ] 初始资金基准线可见且标注数值
- [ ] 无数据时显示空态而非 0

### 8.2 P-02 交易记录

**目标**：找到特定的一笔/一类交易，并快速判断它值不值得复盘。

**筛选区**（单行，不折叠）
| 筛选项 | 类型 | 选项 |
|---|---|---|
| 交易对 | 下拉 | 全部 / 已有交易对 |
| 方向 | 下拉 | 全部 / 做多 / 做空 |
| 策略 | 下拉 | 全部 / 已定义策略 |
| 结果 | 下拉 | 全部 / 盈利 / 亏损 |
| 复盘状态 | 下拉 | 全部 / 待复盘 / 已完成 |
| 关键词 | 输入 | 匹配交易对与形态描述 |

右侧固定显示"筛选结果 N 笔 · 合计净收益"。

**表格列**
开仓时间 / 交易对 / 方向 / 策略 / 入场→出场价 / 净收益 / R / 持仓时长 / 标签（最多 2 个 + 计数）/ 执行分 / 复盘状态。

**交互**
- 行点击进入 P-03。
- 分页每页 25 条，显示页码与总页数。
- 表头下方显示当前筛选集的胜率、盈亏比、手续费汇总。
- 默认按开仓时间倒序。

**验收标准**
- [ ] 任一筛选条件变化后，列表与右侧汇总同步更新
- [ ] 金额为估算值的行显示 `≈`，悬停有说明
- [ ] 空结果有明确文案，不显示空表格
- [ ] 表头在滚动时吸顶（数据超过一屏时）

### 8.3 P-03 单笔复盘

**目标**：把一笔交易的事实、判断、改进动作完整记录下来，这是整个产品的数据来源。

**布局**

1. **顶部操作条**：返回 / 交易 ID / 数据质量角标（估算值、非 USDT 手续费、校验不一致）/ 保存按钮。
2. **缺止损提示条**（条件显示）：缺开仓止损时提示"补齐止损价即可计算 R 倍数，当前该笔不参与 R 相关统计"。这是可执行提示，不是错误。
3. **交易头**：交易对、方向、策略、行情环境、时间区间、持仓时长、形态；右侧三个大数字——净收益、R 倍数、执行评分。
4. **价格轨迹图**（左栏）：仅用成交价还原，绘制开仓/平仓水平线、止损虚线、盈亏区间着色。图中明确标注"非 K 线"。
5. **复盘表单**（左栏）：
   | 字段 | 控件 | 必填 | 说明 |
   |---|---|---|---|
   | 入场理由 | 多行文本 | 否 | 当时看到的信号 |
   | 计划形态 | 输入 | 否 | 突破回踩 / 均线回踩… |
   | 实际执行 | 输入 | 否 | 与计划一致 / 提前入场… |
   | 出场理由 | 多行文本 | 否 | |
   | 计划偏离 | 输入 | 否 | 哪里没按计划做 |
   | 当时情绪 | 下拉 | 否 | 平静/焦虑/急躁/恐惧/贪婪/愤怒/亢奋 |
   | 是否按计划执行 | 下拉 | 否 | 是 / 否 / 未记录 |
   | 执行评分 | 输入 | 否 | 0–100 整数 |
   | 复盘结论 | 多行文本 | 否 | |
   | 下一步要改的一件事 | 输入 | 否 | 必须具体可执行 |
6. **右栏三卡**：盈亏构成（毛收益 − 手续费 + 资金费率 = 净收益，及价格/数量/名义仓位/保证金/杠杆）、风险口径（开仓止损/计划风险/R/MFE-MAE）、标签点选。

**校验规则**
- 执行评分为 0–100 的整数，超范围拒绝保存并提示。
- 所有字段可后补，保存后 `reviewStatus` 置为已完成。
- 标签可多选，点击即切换。

**验收标准**
- [ ] 保存后刷新页面，表单内容与标签完整还原
- [ ] 保存成功后按钮短暂显示"已保存"，并重新拉取该笔数据
- [ ] 缺止损时 R 显示"不可计算"而非 0
- [ ] 价格轨迹图的价格标注与实际成交价一致

### 8.4 P-04 策略分析

**目标**：回答"哪个策略真的在赚钱"，并敢于说"样本不够，不下结论"。

**布局**：2 列卡片，每策略一张。

**卡片内容**
- 顶部：策略名 + 结论徽章（表现正常 / 需要重新评估 / 样本不足）+ 净收益
- 四个小指标：样本数、胜率、期望值、盈亏比
- 净收益横向条形（相对最大绝对值）
- 明细行：R 期望（含样本量）、累计 R、手续费、平均持仓
- 可折叠的策略规则文本

**结论徽章规则**
| 徽章 | 条件 |
|---|---|
| 需要重新评估 | 样本 ≥ 20 且净收益 < 0 |
| 样本不足 | 样本 < 20 |
| 表现正常 | 样本 ≥ 20 且净收益 ≥ 0 |

**验收标准**
- [ ] 每个策略的样本数与交易列表按策略筛选的结果一致
- [ ] 样本不足的策略不显示"需要重新评估"
- [ ] R 期望旁必须显示 R 样本量，避免与总样本混淆

### 8.5 P-05 标签归因

**目标**：把亏损归因到具体行为，而不是"运气不好"。

**布局**：按标签分类分组的表格，空分类不显示。

| 分类 | 说明 |
|---|---|
| 失误标签 | 追高、无计划入场、止损犹豫、逆势加仓、重仓、提前止盈 |
| 做对了 | 按计划止盈、严格止损、等待确认 |
| 行情环境 | 震荡、单边下跌… |
| 形态 | 预留 |

**表格列**：标签 / 出现次数 / 胜率 / 平均每笔净收益 / 累计净收益 / 正负分布条。

**关键规则**
- 标签带极性（正/负/中性），决定颜色与含义：负向标签累计净收益越负，越需要被消除。
- 只统计已带该标签的已平仓交易；无标签交易不进入任何分组，页面底部提示"没有标签的亏损无法被解释"。

**验收标准**
- [ ] 同一标签的"出现次数"等于交易列表中该标签筛选的数量
- [ ] 无数据分类整块隐藏，不显示空表

### 8.6 P-06 系统诊断

**目标**：用透明规则做体检，每条结论都可审计。

**布局**

1. **诊断卡列表**：每条命中规则一张卡，含规则编号 + 名称、等级色条、标题、详情文本、阈值、样本量、关联交易数。
2. **样本不足提示条**：总样本不足时明确显示"不下结论"。
3. **连续盈亏卡**：最长连亏 / 最长连赢 + 每日净收益柱状图。
4. **风险画像卡**：最差单日、缺止损占比、平均计划风险、连亏后放大次数、交易对集中度。
5. **规则清单**：6 条规则的阈值速查。

**规则规格**

| 编号 | 名称 | 触发条件 | 等级 |
|---|---|---|---|
| R1 | 策略失效 | 某策略样本 ≥ 20 且期望值 < 0 | 高 |
| R2 | 过度交易 | 单日笔数 > 日均 × 2 | 中 |
| R3 | 连亏放大 | 连亏 ≥ 3 笔后，下一笔名义仓位 > 前 3 笔均值 × 1.5 | 高 |
| R4 | 止损缺失 | 无开仓止损的样本占比 > 30% | 中 |
| R5 | 手续费侵蚀 | 手续费 ÷ \|净收益\| > 40% | 高 |
| R6 | 计划偏离 | 已复盘样本中未按计划执行占比 > 20% 且样本 ≥ 5 | 中 |

**硬性要求**：每条命中规则必须同时展示「阈值」和「样本量」，且样本不足时不得输出结论。

**验收标准**
- [ ] 所有阈值来自统一配置，页面显示的阈值与实际判定值一致
- [ ] 修改筛选区间后，诊断结果随之变化
- [ ] 关联交易可点击跳转到单笔复盘

### 8.7 P-07 设置

**目标**：配置账户与数据来源，让数据能自动进来；同时让"密钥在哪、同步做了什么"完全透明。

**布局**

1. **账户卡**：账户名、探测到的持仓模式、最近同步时间、初始资金（可改，影响收益率与回撤基准）。
2. **Bitget API 卡**：
   - API Key / Secret Key / Passphrase 三个输入框
   - 保存密钥、测试连接、清除密钥
   - 状态徽章：实盘只读 / Mock 模式
   - 明确说明密钥存放位置与加密方式
3. **数据同步卡**：开始/结束日期、立即同步、清空同步数据；旁边常驻说明同步流程与拒绝 hedge 的策略。
4. **本次同步日志**（同步后展开）：逐行带时间戳的执行记录，失败可直接看出卡在哪一步。
5. **同步历史表**：时间、模式、状态、区间、成交/订单/流水条数、新增数、耗时；点击某行回看该次日志。

**关键规则**

| 规则 | 说明 |
|---|---|
| 未配置密钥 = Mock 模式 | 同步写入内置演示成交，不发任何外网请求，用于验证配对与统计链路 |
| 密钥存储 | AES-256-GCM 加密，密钥文件 `data/.secret.key` 与数据库分离；数据库被单独拷走无法解密 |
| 持仓模式探测 | 同步前读取账户模式；hedge_mode 直接中止并给出提示，不做猜测性配对 |
| 重算保留人工成果 | 重新配对会重建自动生成的交易，但按「交易对 + 开仓时间」恢复原有复盘与标签 |
| 清空同步数据 | 只删 `AUTO_MATCHED` 的交易与成交/订单/流水，人工录入的交易与复盘永久保留 |

**验收标准**
- [ ] 测试连接能返回持仓模式与账户权益
- [ ] 未配置密钥时同步走 Mock 模式且成功产出交易
- [ ] 同步日志逐行可读，失败时能定位到具体步骤
- [ ] 重新同步不会重复插入成交（按 tradeId 去重）
- [ ] 清空同步数据后，人工录入的交易仍在

## 10. 指标口径摘要

完整定义见 `01-数据模型与计算口径.md` §五，此处仅列产品侧必须守住的四条：

1. 所有"盈亏"默认指**净收益**（已扣手续费、已加资金费率），胜率、盈亏比、期望值全部基于净收益。
2. 期望值必须给两个口径：**USDT 口径（全样本）**与 **R 口径（仅 R 可用样本）**，后者必须显示样本量。
3. 回撤基于交易权益（剔除资金划转），不基于账户余额。
4. 缺数据 → 标估算值；不可计算 → 留空。**不允许用 0 顶替。**

## 11. 数据与状态

### 11.1 交易状态机

```
        ┌──────────────┐
        │   OPEN       │ 已开仓未平仓，不参与统计
        └──────┬───────┘
               │ 完全平仓
               ▼
        ┌──────────────┐  人工确认/修正
        │   CLOSED     │◄──────────────┐
        └──────┬───────┘               │
               │ 配对异常               │
               ▼                       │
        ┌──────────────┐               │
        │ NEEDS_REVIEW │───────────────┘
        └──────────────┘
```

### 11.2 复盘状态

`PENDING`（待复盘）→ `DONE`（已复盘）。只要填写并保存任意一个复盘字段即置为 DONE，不强制填满。

### 11.3 配对状态

`AUTO_MATCHED`（系统配对）/ `MANUAL_MATCHED`（人工录入或修正）/ `NEEDS_REVIEW`（无法确认，进人工队列，不参与统计）。
