# 执行评分自动化 · 规则说明

> 状态：已实现（MVP-3）
> 代码：`apps/api/src/analytics/score.service.ts` ｜ 配置键：`AppSetting.score.weights`

## 1. 这个分数在衡量什么

衡量**是否按计划执行**，与盈亏无关：

- 严格止损后亏钱的单子 → 高分
- 逆势摊平后侥幸赚钱的单子 → 低分

所以「自评分 vs 建议分」的差额比分数本身更有价值：偏差持续为正 = 自我评估偏高。

## 2. 公式

```
建议分 = clamp(100 − Σ负向扣分 + Σ正向加分, 0, 100)
负向累计封顶 −70，正向累计封顶 +8
```

**没有任何可评分依据时（未打标签 + 无客观信号）不输出分数**，而不是给 100 分——
宁可不给结论，也不编数字。

## 3. 标签权重（当前默认值）

| 标签 | 分值 | 说明 |
|---|---|---|
| 大亏失控 | −25 | 单笔亏损远超常规，最具破坏性 |
| 逆势摊平 | −20 | 数据：57 笔合计 −3430 U |
| 逆势加仓 | −20 | 同上语义 |
| 反复补仓 | −12 | 49 笔合计 −1550 U |
| 无计划入场 / 追高 / 重仓 | −10 | 入场纪律类 |
| 止损犹豫 | −8 | |
| 提前止盈 | −6 | |
| 零散小单 | −5 | 仓位管理碎片化 |
| 手续费侵蚀 | −5 | |
| 严格止损 | +10 | 纪律类加分 |
| 按计划止盈 | +8 | |
| 等待确认 | +5 | |
| 单次开仓 / 顺势加仓 / 吃到大趋势 | **0** | 入场风格类，只做归因，不参与评分 |

> 为什么入场风格类为 0：这类标签描述"怎么做"，不是"做得好不好"。
> 早期版本给「单次开仓」+10，导致 100 分泛滥（平均 86.7），已修正。
>
> 「顺势加仓」原被打成 NEGATIVE，但 59 笔合计 **+452 U**，已改为 POSITIVE；
> 其评分权重仍为 0——它的价值应体现在策略归因里，不该刷执行分。

## 4. 客观指标（不依赖标签，未打标也能算）

| 指标 | 判定条件 | 扣分 |
|---|---|---|
| 止损未执行 | 有止损价且 `|亏损| > 计划风险 × 1.5` | −12 |
| 单笔异常大亏 | `|亏损| > 历史平均亏损 × 3` | −10 |
| 手续费侵蚀 | `手续费 > 毛收益 × 50%`（仅盈利单） | −6 |
| 超短持仓亏损 | 持仓 < 120 秒且亏损 | −4 |

**缺止损记录不扣分**，只标注「仓位纪律无法评估」——那是数据缺失，不是纪律缺失。

另有一个冲突检测：标签是「严格止损」但没记录止损价 → 输出提示「建议核对」。

## 5. 三种写入模式

| 模式 | 行为 | 用途 |
|---|---|---|
| `suggest` | 只算不写 | 日常查看建议分 |
| `fill` | 只写 `executionScore` 为空的交易 | 批量补齐历史空白 |
| `overwrite` | 全部覆盖（含人工分） | 调完权重后重算 |

人工填分会被标记 `scoreSource = MANUAL`，自动分为 `AUTO`，两者永不静默互覆盖。

## 7. 回滚与调整

- 清空所有自动分：`UPDATE Trade SET executionScore=NULL, scoreSource='NONE', scoreDetail=NULL WHERE scoreSource='AUTO';`
- 调权重：`PUT /api/analytics/score/weights`，只传要改的键即可（其余走默认合并）
- 权重变更不会自动重算，需要再跑一次 `POST /api/analytics/score/batch { mode: "overwrite" }`
