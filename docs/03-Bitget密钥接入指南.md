# Bitget 只读 API 密钥接入指南（小白版）

> 目标：在 Bitget 后台生成一把**只能读、不能交易**的密钥，填进本系统，让交易记录自动同步。
> 全程约 10 分钟。不需要会写代码，只要会复制粘贴。

---

## 开始之前：先搞清楚三件事

**1. 我们要的是三种东西，不是一种**

很多人以为只需要一个"密钥"，其实需要三个值，缺一不可：

| 名称 | 长什么样 | 作用 | 谁生成 |
|---|---|---|---|
| API Key | 一串字母数字，如 `bg_9f3a...c21` | 你的身份标识（相当于用户名） | Bitget 生成 |
| Secret Key | 更长的一串，如 `K2mX...9pQw` | 用来给请求签名（相当于密码） | Bitget 生成，**只显示一次** |
| Passphrase | **你自己设的**，8-32 位 | 第二道口令（相当于取款密码） | **你自己想一个** |

Passphrase 不是 Bitget 给你的，是你在创建时自己输入的。忘了就找不回，只能删了重建。

**2. 一定要选"只读"权限**

本系统只做复盘，不需要下单，也不需要提现。所以权限只勾「读取」。

这样即使密钥泄露，别人也动不了你的钱，最多看到你的持仓和盈亏记录。

**3. Secret 只显示一次**

创建完成的那一刻，Bitget 会显示 API Key 和 Secret Key。**Secret Key 关掉页面就再也看不到了。**

所以创建时请准备好一个安全的地方（比如本机备忘录、密码管理器），先把 Secret 存下来再点关闭。

> 如果实在丢了：不要紧，去 Bitget 把这把 Key 删掉，重新创建一把就行。旧的一删，泄露风险也就没了。

## 第一步：登录 Bitget，进入 API 管理

1. 浏览器打开 `https://www.bitget.com`，登录你的账户（用**主账户**登录，不要用子账户，子账户的密钥读不到主账户数据）。

2. 看页面右上角，鼠标移到你的**头像**上，会弹出菜单。

3. 在菜单里找 **「API 管理」** 或 **「API Keys」**（不同版本叫法略有差异，认准带 API 字样的那一条）。

4. 如果找不到，可以直接访问 `https://www.bitget.com/zh-CN/account/api`（登录状态下）。

进入后会看到一个列表，可能为空（说明你还没创建过），或者有以前创建的 Key。

---

## 第二步：创建 API Key

1. 点右上角 **「创建 API Key」** / **「新建 API」**。

2. 选择 **「系统生成」**（推荐）。
   另一种是"手动输入"，不需要，系统生成更安全。

3. 填写 **备注名**，比如 `复盘系统只读`。
   建议写清楚用途，将来你有好几把 Key 时能一眼区分。

4. 设置 **Passphrase**（就是上面说的那第三样东西）。
   - 自己设一个，8–32 位，包含字母+数字
   - **不要**和你 Bitget 登录密码、资金密码一样
   - 建议写在你的密码管理器里，或者本机一个加密笔记里
   - 记牢它，下一步和以后填系统都要用

5. **最关键的一步：勾选权限**

   权限列表大致长这样（叫法可能略有差异）：

   | 权限项 | 要不要勾 | 说明 |
   |---|---|---|
   | 读取 / Read | **必须勾** | 读账户、订单、成交，这是我们的命脉 |
   | 现货交易 / Spot Trade | **不勾** | 用不到 |
   | 合约交易 / Futures Trade | **不勾** | 用不到，勾了就是给自己留风险 |
   | 划转 / Transfer | **不勾** | 千万别勾，这能搬钱 |
   | 提币 / Withdraw | **不勾** | 绝对不能勾 |

   > 一句话：**除了「读取」，其他一个都别勾。**

   注意：有些版本把权限拆成「读取账户」「读取交易」两项，两个都勾上。我们要读的是**合约成交明细**，如果只勾了现货读取，合约的数据会读不到（表现为同步成功但成交 0 条）。

6. **IP 白名单（建议填，但可以先跳过）**

   页面会有一个"绑定 IP 地址"的输入框。
   - 有固定 IP（公司网络/云服务器）→ 填上，最安全
   - 家里宽带/手机热点，IP 天天变 → 先留空，留空就是任何 IP 都能用（安全性低一点，靠"只读权限"兜底）
   - 留空的话，注意别把 Key 发给别人

7. **安全验证**：输入邮箱验证码、手机验证码，可能还有谷歌验证码（如果你开了 2FA）。

8. 点 **「提交」/「确认」**。

## 第三步：把三个值抄下来（这一屏只有一次）

创建成功后，页面会弹出一屏，显示：

```
API Key:      bg_xxxxxxxxxxxxxxxx
Secret Key:   K2mXxxxxxxxxxxxxxxxxxxxxxxx
Passphrase:   (你刚才自己设的那个，页面不一定回显)
```

**现在立刻做两件事：**

1. 把 **API Key** 和 **Secret Key** 复制到一个你信得过的地方（本机备忘录就行，别发微信、别发群里）。
2. 确认你记得住 **Passphrase**。

> 页面一关，Secret Key 永久不可见。丢了只能删 Key 重建。
>
> 也**不要截图**——截图会同时包含 Secret，发出去就漏了。

## 第四步：把密钥填进系统

密钥有两个存放位置，任选其一（也可以两个都用）：

| 方式 | 位置 | 适合 |
|---|---|---|
| **A. 写进 .env**（推荐，一次配好永久生效） | `apps/api/.env` | 只在自己电脑用、不想每次点页面 |
| B. 页面保存 | 加密存于 `data/secrets/` | 想随时切换、不想动配置文件 |

**优先级：页面保存 > .env**。页面里保存过的会盖住 .env；点「清除密钥」会回落到 .env。

### 4.0 方式 A：直接写 .env（不打开页面也能配好）

用任意文本编辑器打开 `apps/api/.env`，把这四行填上：

```ini
BITGET_API_KEY=你的 API Key
BITGET_SECRET_KEY=你的 Secret Key
BITGET_PASSPHRASE=你创建 Key 时设的 Passphrase
```

三个都填了才生效（缺一个视为未配置）。填完**重启后端**：

```bash
# 在跑 pnpm dev 的终端里 Ctrl+C，然后重新
pnpm dev
```

启动后再打开设置页，你会看到绿色提示：

```
已从 .env 读取密钥  bg_9f3a****c21｜如需更换，改 apps/api/.env 后重启，或在下方填写保存覆盖
```

> `.env` 已经在 `.gitignore` 里，不会被提交到仓库。但也别把它发到群里。

### 4.1 方式 B：在页面里填

#### 4.1.1 启动系统

打开「终端」（Mac 上按 `Command + 空格`，输入 `终端` 回车），进入项目目录后执行：

```bash
cd <项目根目录>   # 例如本机上的 trading-review 目录
pnpm dev
```

看到下面两行就算起来了（第一次可能要等十几秒）：

```
前端：http://localhost:5173
后端：http://127.0.0.1:3000/api/health
```

浏览器打开 `http://localhost:5173`。

#### 4.1.2 进设置页

左侧导航栏最下面，点 **「设置」**。

你会看到上面两张卡：左边「账户」，右边「Bitget API 配置」。

右边这张卡右上角现在显示的是橙色徽章 **「Mock 模式」**——意思是还没配密钥，同步会写演示数据。

#### 4.1.3 填三个框

在「Bitget API 配置」卡里，有三个输入框：

| 输入框 | 填什么 |
|---|---|
| API Key | 第三步复制的那串 |
| Secret Key | 第三步复制的那串（输入时显示为圆点，正常） |
| Passphrase | 你自己设的那个口令 |

**逐字核对**，特别是容易混的字符：
- `0`（数字零）和 `O`（大写字母 O）
- `1`（数字一）和 `l`（小写字母 L）和 `I`（大写字母 i）
- 前后有没有不小心多复制了**空格**

> 90% 的"签名错误"都是复制时带了空格，或者把 Secret 复制成了 API Key。

#### 4.1.4 点「保存密钥」

点完之后：
- 三个输入框会清空（这是正常的，密钥已经加密存到本地了，不会留在页面上）
- 卡片右上角徽章从「Mock 模式」变成蓝色 **「实盘只读」**
- 上方出现一行提示："已配置：bg_9f3a****c21"（只显示头尾几位，中间打码）

如果徽章没变，说明保存没成功，看页面有没有红色提示。

#### 4.1.5 点「测试连接」

这一步是**真正的验证**。系统会拿你填的密钥去 Bitget 读一次账户信息。

> 不需要先点「保存密钥」——三个框都填了就直接测，测完再决定存不存。

**成功的样子（真实接口）：**

```
连接成功（真实接口）｜持仓模式 one_way_mode｜权益 12.34｜使用刚填写的密钥（未保存）
```

- `one_way_mode` = 单向持仓，符合要求，可以继续
- `hedge_mode` = 双向持仓，下面会有一条黄色警告，**需要先去 Bitget 切换**（见文末排错）

**没连上的样子：**

| 提示 | 含义 |
|---|---|
| `没有用真实密钥测试` / 徽章显示 MOCK | 密钥没读到，返回的是内置假数据（权益永远是 12.34） |
| `无法连接到 api.bitget.com（网络不通，不是密钥问题）` | 网络被拦，见文末「网络连不上怎么办」 |
| `接口错误 40006 Invalid signature` | 密钥内容填错了，翻到文末排错表 |

> **怎么一眼看出是不是真连上了**：看徽章。橙色 `Mock` = 假数据，蓝色 `实盘只读` = 真密钥。再看权益数字，Mock 模式永远返回 `12.34`。

## 第五步：第一次同步

测试连接通过后，往下滚到 **「数据同步」** 卡片。

### 5.1 选日期范围

| 输入框 | 填什么 |
|---|---|
| 开始日期 | 你想拉多久的历史。第一次建议填 **3 个月前**（比如今天 11 月，填 `2026-08-01`） |
| 结束日期 | 默认是今天，不用改 |

> 第一次多拉一点，之后每次只需要点同步，重复的会自动去重，不会重复入库。

### 5.2 点「立即同步」

按钮会变成「同步中…」，大概几秒到几十秒（历史越长越久）。

### 5.3 看日志

同步完成后，下方会自动展开 **「本次同步日志」**，像这样：

```
[10:52:54] 开始同步 2026-08-01 00:00 → 2026-11-04 23:59（LIVE）
[10:52:54] 账户读取成功，持仓模式 one_way_mode
[10:52:55] fills 第 1 页：100 条，继续翻页
[10:52:56] fills 第 2 页：37 条，已到末页
[10:52:56] 成交 137 条，新增 137 条，去重 0 条
[10:52:57] 订单 137 条，新增 137 条
[10:52:58] 流水 24 条，新增 24 条
[10:52:59] 配对完成：平仓 41 笔，持仓中 2 笔，恢复历史复盘 0 笔
```

**逐行读，卡在哪一行一目了然。**

### 5.4 确认结果

往下看 **「同步历史」** 表格，最新一行应该是：

- 模式：`LIVE`
- 状态：绿色 **成功**
- 成交 / 订单 / 流水：有数字
- 新增：有数字

然后去左边 **「交易记录」**，应该能看到新同步进来的交易。

## 第六步：验收（5 项，全部打勾才算真的接通）

| # | 检查 | 在哪看 | 通过标准 |
|---|---|---|---|
| 1 | 徽章变成「实盘只读」 | 设置页右上 | 蓝色，不是橙色 |
| 2 | 测试连接成功 | 设置页 | 显示持仓模式 + 权益数字 |
| 3 | 同步状态成功 | 同步历史表 | 绿色「成功」 |
| 4 | 成交条数 > 0 | 同步历史表 | 不是 0 |
| 5 | 交易列表有新记录 | 交易记录页 | 出现你没手动录入过的交易 |

如果第 4 项是 0（成交 0 条），但同步显示"成功"，说明**日期范围内确实没有成交**，或者**权限没勾合约读取**。先换个更大的时间范围再试；还是 0 就去 Bitget 检查权限。

## 出错了怎么办：对照表

系统会把 Bitget 返回的原始报错显示出来。按关键字对照：

### 先说一个特殊错误：统一账户不支持经典接口

如果你看到这句：

```
您处于统一账户模式，暂不支持调用经典账户接口
```

**这不是你的错，也不是密钥错了。** Bitget 现在有两套账户体系，接口完全不互通：

| | 经典账户 | 统一账户（UTA） |
|---|---|---|
| 接口版本 | v2（`/api/v2/mix/...`） | v3（`/api/v3/trade/...`） |
| 价格字段 | `price` | `execPrice` |
| 数量字段 | `baseVolume` | `execQty` |
| 成交 ID | `tradeId` | `execId` |
| 分页参数 | `idLessThan` | `cursor` |
| 单次查询跨度 | 最多 7 天 | 最多 30 天 |

资产达到 1000 USD 的账户可以被升级为统一账户，升级后原来的 v2 接口全部失效。

**本系统已自动处理**：连接时会先试经典接口，一旦收到上面这句报错，立刻自动切到 v3 重试，并把结果记到账户上，下次直接走 v3。你在设置页会在「账户」卡里看到类似 `UTA` / `统一账户（v3）` 的标记。

如果切换后仍失败，通常是这两个原因：
1. 该 Key 没有合约（futures）读取权限 → 回 Bitget 补勾
2. Key 是子账户的 → 用主账户的 Key

---

其他常见错误：

| 你看到的现象 | 最可能的原因 | 怎么解决 |
|---|---|---|
| `Invalid signature` / 签名错误 | Secret Key 复制错、带了空格、前后顺序填反 | 清空三个框重新填。注意 Secret 和 API Key 不要填串 |
| `sign signature error`（但"测试连接"是成功的） | 这是**程序侧 query 参数排序问题**，不是你的密钥问题 | 已修复：Bitget 要求 query 参数按 key 升序参与签名。若旧版本仍报，重启后端即可 |
| `Invalid API key` / 401 | API Key 复制不完整 | 回 Bitget 复制完整的 API Key，注意别漏尾巴 |
| `Invalid passphrase` / 密码错误 | Passphrase 记错了 | 忘了只能删除 Key 重建；确认没有大小写错误 |
| `Invalid timestamp` / 时间戳错误 | 你电脑的系统时间不准 | 打开「系统设置 → 通用 → 日期与时间」，开启**自动设置** |
| `IP` 相关报错 | 创建 Key 时绑了 IP 白名单，但你现在的 IP 变了 | 两种办法：去 Bitget 把白名单改成当前 IP，或清空白名单 |
| `权限不足` / `no permission` | 只勾了现货读取，没勾合约读取 | 回 Bitget 编辑这把 Key，补勾合约/读权限 |
| 同步成功，但成交 0 条 | ① 时间范围内真没交易 ② 权限缺 ③ 这是子账户的 Key | 先扩大日期范围；再查权限；再确认用的是主账户 |
| 提示「双向持仓模式」 | 你的合约账户是 hedge_mode | **不需要处理**：系统会按多头、空头两条腿分别配对。只是提醒你同一交易对可能同时存在多单和空单 |
| 页面打不开 / 一直转圈 | 后端没起来 | 终端里看有没有报错；访问 `http://127.0.0.1:3000/api/health` 应该返回一段 JSON |
| 保存后徽章还是「Mock 模式」 | 保存请求失败 | 看页面是否有红色提示；刷新页面再看 |

> 上面关于错误码的描述以文字关键字为准——Bitget 的具体数字码会随版本调整，认字比认数字可靠。

## 安全须知（请务必读完）

**1. 密钥泄露了怎么办**

立刻去 Bitget 的 API 管理页面，**删除这把 Key**。删掉之后它立刻失效。
然后在本系统设置页点 **「清除密钥」**，重新创建一把新的填进来。

**2. 不要做的事**

| 不要 | 原因 |
|---|---|
| 把 Secret 发到微信/QQ/群里 | 聊天记录会被备份、被转发 |
| 截图发出去（包括发给 AI） | 截图里通常同时含 Key 和 Secret |
| 把 Secret 粘到在线工具/网页版转换器 | 那些网站可能记录你的输入 |
| 勾选「交易」「划转」「提币」权限 | 一旦泄露就是真金白银的损失 |
| 用同一把 Key 到处填 | 出事时无法判断是哪泄露的 |

**3. 密钥存在哪**

- 系统不会把密钥明文存进数据库。
- 加密后存在 `data/secrets/` 目录，加密文件是 `data/.secret.key`。
- 这两个文件都在你本机，不上传任何服务器。
- **备份提醒**：`data/` 目录如果换电脑要一起带走；`data/.secret.key` 丢了，密钥就得重新填一遍（数据不会丢）。

**4. 这套系统能做的事的边界**

只读权限下，系统**永远不可能**替你下单、平仓、提币。它连这些接口都不会调用。

## 附：不用界面，用命令行也行

如果你更喜欢命令行，或者想确认界面是不是真的存进去了：

```bash
# 1. 看当前配置状态（应该显示 configured: true）
curl --noproxy '*' http://127.0.0.1:3000/api/sync/config

# 2. 写入密钥
curl --noproxy '*' -X PUT http://127.0.0.1:3000/api/sync/config \
  -H 'Content-Type: application/json' \
  -d '{"apiKey":"你的API Key","secret":"你的Secret","passphrase":"你的Passphrase"}'

# 3. 测试连接
curl --noproxy '*' -X POST http://127.0.0.1:3000/api/sync/test

# 4. 执行同步（同步 2026-08-01 至今）
curl --noproxy '*' -X POST http://127.0.0.1:3000/api/sync/run \
  -H 'Content-Type: application/json' \
  -d '{"from":"2026-08-01"}'

# 5. 清空密钥
curl --noproxy '*' -X DELETE http://127.0.0.1:3000/api/sync/config
```

> `--noproxy '*'` 是为了绕开系统代理直连本机，不加有时会报「连接被拒绝」。

**如果你用 Postman / Apifox / 浏览器插件调试**：

- `/api/sync/test` 和 `/api/sync/reset` **不需要请求体**，直接 POST 即可（早期版本会因「声明了 JSON 但 body 为空」返回 400，现已修复）。
- `/api/sync/run` 的 body 可以完全省略，省略时默认同步最近 90 天。
- 如果还是遇到 `Body cannot be empty when content-type is set to 'application/json'`，说明后端跑的是旧代码，重启一次（`pnpm dev:api`）即可。

## 附：网络连不上 Bitget 怎么办

### 先做个判断：是网络问题还是密钥问题

设置页有个 **「网络自检」** 按钮，它不带密钥、只做两件事，用来把两类问题彻底分开：

| 检查项 | 通过的样子 | 不通过意味着 |
|---|---|---|
| DNS 解析 | `api.bitget.com → 104.18.x.x` | 域名解析被污染/失败 |
| HTTPS 请求 | `HTTP 200｜{"code":"00000",...}` | **网络层被拦截，和密钥无关** |

典型的不通长这样：

```
DNS 解析     ✓  api.bitget.com → 104.18.14.166  · 12ms
HTTPS 请求   ✗  无法连接到 api.bitget.com（网络不通，不是密钥问题）· 343ms
```

**DNS 能解析、但 HTTPS 在几百毫秒内就被切断**——这是国内访问 Bitget 最常见的现象，说明需要代理。

### 解决办法（两种，任选一个）

**方式一：代理开 TUN / 增强模式（最省事，推荐）**

Clash、Surge、Stash 这类工具都有「TUN 模式」「增强模式」「虚拟网卡」的开关。
打开它之后，**Node.js 的流量也会被接管**，不需要改任何配置，重启后端即可。

只开「系统代理」通常**不够**——Node 自带的 fetch 不读系统代理设置，会绕过代理直连，表现就是浏览器能打开 bitget.com，但这里一直"网络不通"。

**方式二：给后端单独配代理（本仓库已预置）**

打开 `apps/api/.env`，会看到这一行：

```
BITGET_PROXY=http://127.0.0.1:7890
```

- 端口换成你自己代理的 HTTP 端口（ClashX 默认 7890，Clash Verge 常是 7897）
- **不使用代理时把它注释掉**（行首加 `#`）
- 改完**必须重启后端**（`Ctrl+C` 后重新 `pnpm dev:api`）

启动日志出现这行就说明生效了：

```
[BitgetClient] Bitget 请求将经由代理：http://127.0.0.1:7890
```

网络自检里也会显示 `代理 http://127.0.0.1:7890`。

> 为什么不用常见的 `HTTPS_PROXY`？因为它太容易被系统/终端/IDE 里的同名变量抢占，
> 而且优先级不明确。`BITGET_PROXY` 是这个项目专用的开关，读到了就一定用。
> （程序仍兼容 `HTTPS_PROXY` / `HTTP_PROXY`，只是优先级最低。）

### 还是不通？

- 换一个节点（香港/日本/新加坡一般可以，美国节点偶尔被风控）
- 确认代理的「规则模式」没把 `api.bitget.com` 放进直连名单（很多规则集的默认策略是直连国外交易所）
- 用终端验证一下，绕开本系统：
  ```bash
  curl -m 8 https://api.bitget.com/api/v2/public/time
  ```
  返回 `{"code":"00000",...}` 就说明网络 OK，问题在系统之外。

> 去 Bitget 建一把**只勾「读取」**的 Key → 记下 **API Key / Secret / 自设的 Passphrase** 三个值 → 填进「设置」页 → 点**测试连接**看到持仓模式 → 点**立即同步**看日志。
